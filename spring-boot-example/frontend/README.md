# Lens 搜索前端

保留 `search-ui` 原型的紧凑布局，使用 Vue 3 Composition API、单文件组件与 Vite。生产入口位于本目录；`search-ui/` 仅为独立静态设计原型。SQL / PPL 原文和结构化条件交给后端执行。

## 前端结构

- `src/App.vue` 组合页面和弹窗，输入通过 `v-model` 绑定，列表、图表、状态和按钮通过 Vue 模板更新。
- `src/composables/useWorkspace.js` 管理查询、分页、时间、筛选和历史；`useExport.js` 管理冻结导出上下文、下载和可恢复的任务轮询。
- `src/components/` 包含查询编辑器、图表、结果表、日志行、字段探索和弹窗；`src/query-assist.js` 只提供响应式补全状态与事件处理，候选由 Vue 渲染。
- 浏览器原生能力（焦点、光标选区、滚动、尺寸测量、模态框和下载）通过组件 ref 调用；界面不再通过 DOM 查询、HTML 字符串或手动节点替换维护。
- `npm test` 包含编译真实 Vue 单文件组件后挂载的整页交互回归，以及补全协议和字段语义测试。后端接口和 Java 打包入口保持一致。

## 开发与打包

需要 Node.js 20.19+ 或 22.12+，以及已启动的 Spring Boot 示例：

```bash
cd spring-boot-example/frontend
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/`，开发和预览服务器把 `/search`、`/ui` 转发到 `http://127.0.0.1:8080`。其他后端地址可设置 `QUERY_API_TARGET=http://127.0.0.1:8081 npm run dev`。`npm run build` 生成 `dist/`；`npm run preview` 使用 5174 端口。

前后端独立构建和启动。后端在 IDE 中直接运行 `QueryApplication`，或通过 `./gradlew :spring-boot-example:bootJar` 构建后运行 JAR；仅提供 HTTP 接口，不依赖 Node.js、不构建或打包前端。前端使用上述 Vite 命令启动；独立部署时执行 `npm run build` 并由静态服务器托管 `dist/`，将 `/search` 和 `/ui` 反向代理到后端。浏览器接口采用相对路径，支持应用上下文路径。

## 查询行为

- 明细和柱状图分别调用 `POST /search`：明细提交 `include:["rows"]` 和 `page`，先显示结果；随后柱状图提交 `include:["histogram"]` 和 `histogram`，不携带分页。两次请求复用相同的语句、筛选和服务端解析后的绝对时间范围。语句中的表名是唯一查询来源，默认表配置仅用于快捷模板；模板不自动添加 `LIMIT/head`。
- 默认使用 PPL 和最近 24 小时。时间范围提供昨天、今天（零点至当前）、最近 24 小时、最近 7 天和自定义；自定义通过日期时间选择器填写，支持毫秒。时间字段和业务时区采用数据源配置，默认 `timestamp` / `Asia/Shanghai`，不显示输入项。选择器中的时间按业务时区提交给后端解析，范围为 `[from,to)`。后端返回 `resolvedTimeRange` 后，柱状图、翻页和导出复用该固定范围。
- 字段筛选采用 `eq/ne/gt/gte/lt/lte/in/is_null/is_not_null/contains`，按 AND 提交。数值和布尔字段按配置类型提交；`in` 输入 JSON 数组。`contains` 按字符串字面量包含处理。
- 页码和每页条数全部在后台执行，使用 `hasNext` 判断下一页，不用当前页行数代表总命中数。默认每页 20 条，可手动选择 8、20 或 50 条；服务端上限低于 20 时，默认使用该上限。调整窗口或表格高度不会改变每页条数或重新查询。
- 翻页和调整每页条数仅请求 `include:["rows"]`，保留原有图表，也不中止仍在加载的图表。图表直接使用后台 `histogram.buckets:[{from,to,count}]`，不会从明细行推导计数；不支持和执行失败分别显示原因。点击桶提交其绝对时间范围并回到第一页。
- 明细和柱状图独立显示加载状态、耗时与告警；明细提示显示在数据区域，柱状图提示显示在时间分布区域，并保留后端 `detail` 中的具体算子。图表加载期间可浏览和翻页，也可单独停止图表加载；图表失败不影响已返回的明细。修改条件、重新搜索、取消整次查询或离开页面时，中止过期请求并阻止旧响应覆盖当前结果。
- 编辑语句、时间或筛选后，下一次查询从第一页开始；旧结果保留原有页码并提示条件已修改。手工编辑等待执行；筛选应用、时间预设和桶点击直接搜索。保留请求中止和版本检查，防止旧响应覆盖新条件。
- 刷新期间保留上次结果并显示顶部进度条，失败或取消也保留旧数据；新结果通过 Vue 响应式模板与稳定的 key 更新，避免整块清空闪动。同一查询刷新保留滚动、字段展开和未变化日志的展开状态；切换查询或翻页成功后回到顶部。输入语句不重画结果，翻页不重画图表。
- 历史记录保存语句、数据源、时间范围和筛选，最近 20 条保存在浏览器；载入后手动执行。相对范围在重新搜索时重新解析。
- 原始采集日志优先展示时间、正文、级别和来源，采集元数据在字段面板中折叠。点击行或展开箭头可在表格内查看 `extracted` 的解析字段，支持键盘 Enter / Space；“全部字段”打开完整记录详情。展开期间保留每页条数，不因详情高度重新查询。
- 普通投影和聚合结果按返回的列顺序展示；详情和 JSON 始终保留完整原始列、重复别名、null、嵌套值和精确数值。
- 字段探索面板中，点击字段名查看当前页最常见的 10 个值及出现次数；数值不代表整个时间范围的分布。直接读取单个源表的查询（PPL `source=表`、SQL `SELECT * FROM 表`）可用 `＋ / −` 包含或排除值，复用 `POST /search` 的结构化 `filters`，重新查询所选时间范围并回到第一页。null 使用 `is_null/is_not_null`；数字、布尔值保留原类型，超出安全精度的数值、对象和数组不提供快捷筛选。别名、投影、计算或聚合结果仅提供取值预览与列选择，源字段条件仍通过“添加源字段筛选”设置。
- 勾选字段选择表格显示列，至少保留一列；“全部”显示所有返回列，“默认”恢复日志视图或完整结果表。相同字段结构的翻页、刷新和筛选保留选择，切换数据源、语言或结果字段结构后恢复默认。列选择只影响表格，JSON、记录详情和导出继续使用完整结果。窄屏可通过结果工具栏的“字段 / 列”打开面板。

`GET /ui/config` 提供数据源显示配置和顶层 `maxPageSize`，前端按该上限约束每页条数并禁用超限选项。每个 source 可包括 `table`（快捷模板默认表）、`timeField`、`timeZone` 和 `sourceFields:[{name,type}]`。直接读取源表成功后，其返回字段可补充源字段筛选的候选；结果别名不作为源字段推断。未配置字段时，也可在筛选框显式输入源字段名，后端负责校验。时间字段通过数据源配置指定，不依赖该列出现在查询结果中。

## 上下文补全

编辑器通过 `GET /ui/query/completions` 查询支持的语言，通过同一路径的 `POST` 提交 `{language,source,text,caret,documentVersion,trigger}` 获取当前光标位置的候选。目前启用 PPL，SQL 后续接入同一协议；前端按服务端能力启用提示，没有语言专属的语法判断。语句和光标会发送至查询服务，浏览器不再下载或解释 ANTLR 语法包。

输入、聚焦空编辑器或移动光标后以 150ms 防抖更新建议，`Ctrl+Space` 可手动触发，方向键选择、`Enter/Tab` 插入、`Escape` 关闭，也可点击候选；`⌘/Ctrl+Enter` 仍执行查询。接受候选后立即请求下一步，例如 `source` → `=` → 真实表 / 索引 → `|` → 命令 → 字段 → 运算符。候选显示用途或字段类型说明。

后端根据当前语句解析表及管道输出，按需读取数据源真实表结构；配置默认表、`sourceFields` 和上次查询结果不会代替语句的字段作用域。前端直接应用候选的 `textEdit:{from,to,newText}`，按 UTF-16 的 `[from,to)` 范围替换，保留光标后内容；可选 `caretOffset` 将光标放在函数括号等插入内容内部。

命令、函数、参数名、枚举值及必需符号统一从当前生成的 ANTLR parser ATN 推导，不维护补全命令白名单。没有 `literalName` 的固定词法别名也从 lexer ATN 枚举。空输入仍按搜索场景优先提示 `source/search/index`；显式输入 `makeresults/rest/multisearch` 等顶层命令后也使用同一语法补全。当前执行器不支持的能力单独过滤，ML 是否显示取决于所选数据源是否注册了 provider。

语法候选先经过 `PplSuggestionContext` 的当前位置策略，再提供给界面。`input/accept/manual` 使用相同边界；普通函数、限定名称或其他可选表达式分支通过明确前缀进入，不把完整语法候选集直接作为默认菜单。

| 当前位置 | 默认提示 | 不应混入 |
| --- | --- | --- |
| 来源已完成 | `|`，内层子查询可有 `]` | 字段、时间参数、数字示例；此处不查字段 |
| 管道之后 | 可执行的命令 | 表字段、函数、字面量 |
| 字段或表达式起始处 | 当前作用域字段及需要的结构入口 | 全量普通函数、真假值/日期常量、无关数字示例 |
| 条件位置中字段或计算表达式已选完（where / JOIN ON / CASE / IF / count(eval) / reset） | 按类型提示比较、列表、空值或文本匹配 | 算术运算、重复的 `==`；文本不默认提示大小比较，数值不提示文本匹配 |
| 复合字段 / 类型为 `any` 等未确定字段 | 空值判断、相关子字段；未确定类型明确标记信息不完整 | 猜测数值或字符串运算；输入前缀不能绕过类型约束 |
| 可重复字段列表选完一项 | 逗号、管道、命令参数或必需的后续结构 | 再次展开整表字段；继续输入前缀或分隔符后恢复字段提示 |
| 比较运算符之后 | 数字/字符串输入说明，布尔字段提示 `true/false` | 猜测字段值、整表字段、全量函数；字段或函数前缀可开启表达式 |
| 条件已完成 | `and/or/xor`、管道、当前嵌套层的闭合符号或命令要求的后续结构 | 再次展开当前表达式的比较、字段和函数；明确输入运算符可扩展表达式 |
| `BETWEEN` 下界完成 / 等待边界值 | `and` / 按目标类型等待输入 | 把范围分隔符当逻辑连接后再次铺开字段和运算符 |
| 新名称、别名 | 等待用户输入；输入后提示下一语法步骤 | 现有字段替代别名、表达式常量 |
| 参数名 / 参数值 | `=` / 声明的枚举、值或字段位置 | 别的参数位置的字段、函数和数值 |
| `stats` 聚合与分组 | 聚合入口、分组字段、`span` | 普通标量函数全集 |

函数头按实际语法起始路径识别，内部 `AS/FROM/IN/ELSE` 和函数参数中的比较词不会插入函数括号。空参数能否闭合还考虑执行器签名；PPL 聚合的独立语法保持有效，例如 `count()`。参数去重限于当前调用。`convert`、`foreach` 和 ML 动态名称读取执行器定义；`graphlookup edge=` 按关联表提示两端字段。时间分桶不提示数值对数步长，分桶字段不包含已知不支持的布尔/复合类型；未知类型仍保留，不假装完成完整语义诊断。

字段绑定区分 JOIN 两侧、lookup 输入/输出以及嵌套 search、appendpipe/appendcol 的作用域。投影、排除、重命名、计算字段、转换、分桶和聚合更新后续可见字段；字面点号字段与结构化路径分别引用。普通顶层字段优先于元字段和展开字段，最多展示 100 项；截断为当前语法项预留位置，防止大量字段挤掉 `span`、括号等续接，字段部分通过前缀缩小范围。

`stats by span(字段, 间隔)` 会提示字段、类型对应的步长和后续分组，并向下一管道传播分组列或别名；`eventstats/streamstats` 的 span 仅用于分区，不产生额外分组列。尚未确定的 JOIN/多表输出、动态列、pivot 和通配符重命名会明确标记字段信息不完整。能确定保留输入列的命令只提示已知字段；会替换结果结构的命令不沿用旧字段冒充输出。语法提示仍可使用。补全不会采样字段值，也不替代实际查询的语义校验。

验证分为几层，不能把词条覆盖当作连续流程覆盖：

- `PplGrammarCoverageTest` 从执行语法发现管道/顶层命令、参数规则和函数族，验证词条和前缀。
- `PplContinuationCoverageTest` 对每个支持的管道命令执行完整流程：选候选、应用真实 `textEdit/caretOffset`、检查下一步、解析最终语句，再接下一管道；自由输入值和新名字单独标记。重点嵌套与可选规则的有限路径直接从 ATN 枚举，缺少完整流程或明确排除理由时失败。这是明确范围的分支门禁，不宣称穷举无限嵌套及所有组合。
- `PplGuidanceTest` 对各类位置同时断言必须出现和不得出现的类别/词条，并沿实际接受流程验证条件、列表、参数、嵌套函数、别名、关联表和子查询。连续流程测试的每一步还检查小型测试表不会触发超大默认菜单，选中参数名后下一步只能是等号。
- `PplFilterRegressionTest` 覆盖过滤与文本编辑风险，包括嵌套调用、函数内部关键字、重复参数作用域、空格分隔、前缀歧义和光标中间替换。
- `PplOperatorGuidanceTest` 验证数值、文本、布尔、时间、复合/未知类型的运算符，包含父字段替换为具体字段、别名、括号和空值判断的完整流程。算术在数值计算位置保留；基础算术、显式 CAST 和布尔表达式会向后续管道传播已知类型，其他无法确定的类型保持未知。
- `PplOperatorJourneyTest` 使用同一份可执行表 Schema 获取真实元数据并执行查询，覆盖字符串、整数、DECIMAL、布尔、DATE/TIME/TIMESTAMP、ROW/MAP、数组和 ANY。条件位置、计算/函数参数、投影别名和聚合输出都校验运算符的出现与排除；接受真实编辑后继续请求，完整走完每个默认比较运算符，以及括号/NOT、CASE/IF、count(eval)、reset 前后和下一管道，校验执行结果。无法从运行时元数据确定的函数结果保持未知类型。
- `PplSourceBoundaryTest` 同时验证应出现与不应出现的候选：来源完成后严格只有管道/合法子查询闭合，不得提前查询字段；显式开启高级分支和进入字段位置后再正常补全。
- `PplContextCompletionTest` 验证表关联和字段作用域；通用 ANTLR 类的测试验证状态机、词法词条和参数识别。

前端另测连续接受、已有括号与光标后内容、选择事件和过期响应；这些使用响应 fixture 的协议测试不能替代后端真实候选测试。接受建议后的同位置 `select` 事件不会取消正在进行的下一步请求。

组合输入期间暂停提示；输入、切换语言或来源、关闭建议时中止旧请求，并检查文档版本、完整上下文与焦点，避免旧表字段覆盖新提示。元数据部分不可用时保留可用候选并显示原因，接口失败会显示可重试状态，不影响查询执行。前端交互回归执行 `npm test`，生产构建执行 `npm run build`。

## 导出

同步 CSV 使用 `POST /search/export`；异步使用 `POST /search/export/tasks`、`GET /search/export/tasks/{id}` 和 `GET /search/export/tasks/{id}/file`。两者都使用最后一次成功查询的完整冻结上下文，包含绝对时间与 filters，保留用户 `LIMIT/head`，不包含 UI 的 `page/histogram/include`。

异步提交后页面编辑不影响任务。任务 ID 保存在浏览器，刷新可恢复轮询；暂停刷新仅停止浏览器轮询。异步文件使用附件链接直接下载。停止查询等待仅中止浏览器请求，服务端可能继续执行。
